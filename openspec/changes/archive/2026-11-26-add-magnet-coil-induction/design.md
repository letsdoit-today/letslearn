# Design

## Context

站点已有导体棒切割磁感线演示（`src/demos/ElectromagneticInduction.tsx` + `src/lib/physics/induction.ts`），其物理内核是「外力驱动的棒运动 → 欧拉积分 → 时间常数 τ 自适应时间轴」。本次新增的是另一种物理载体，见 proposal.md 的 Why。

现有可复用基建：

- `useSimulation`（`src/hooks/useSimulation.ts`）：预计算帧序列 `{ t }[]` 并按时间轴播放，要求帧按 `t` 单调递增。
- `useSVGScene`：挂载时初始化 svg.js 场景，后续由 demo 自行重绘。
- 共享组件：`DemoPage`、`SimulationCanvas`、`DemoSidebar`、`KpiBar`、`ParamSlider`、`DemoControls`、`CanvasLegend`、`PrincipleCard`。
- 语义色：`palette.field`（磁场）、`palette.current`（感应电流）、`palette.emf`（电动势）已存在，无需新增。
- 路由与验证：`scripts/prerender.js` 与 `scripts/verify-layout.mjs` 都从 `src/lib/demos.json` 派生路由，新条目自动纳入预渲染与布局断言。
- `public/sitemap.xml` 是唯一仍靠人工维护的派生产物，历史上已漏过 `lever-balance`、`pendulum-oscillation`，并出现过缺失结尾斜杠的格式不一致；`dist` 已被 `.gitignore` 忽略，故站点地图必须落在 `public/` 下随 `vite build` 复制进产物。

约束来自既有规格：`demo-workspace-layout` 要求侧栏只放控制、KPI 条 4–6 项只放逐帧变化量、恒定派生量单行小字；`demo-canvas-legend` 要求图例在画布下方正常文档流；`electromagnetic-induction` 的既有需求不得被改动。

## Goals / Non-Goals

**Goals:**

- 用单一物理内核（`src/lib/physics/magnetCoil.ts`）产出一份帧序列，场景、图表、KPI、指针全部从同一帧读取，保证画面与读数自洽。
- 让「磁通量极大而电动势为零」与「累计电荷与快慢无关」两条结论在画面上可直接读出，而非靠文字说明。
- 帧结构、采样约定与既有演示保持一致（约 800 帧），使预渲染与布局验证无需特殊处理。
- 把 `sitemap.xml` 从人工维护改为由 `demos.json` 生成，使新增演示时不再存在「忘记同步」的可能。

**Non-Goals:**

- 不引入线圈自感导致的 RL 瞬态（准静态处理，理由见 Decisions）。
- 不实现手动拖拽磁铁。
- 不实现磁铁倾斜、线圈多匝绕制细节或互感耦合的三维场仿真。
- 不改造 `robots.txt`、页面内 `<link rel="canonical">` 或 Open Graph 的生成方式。

## Decisions

### 1. 独立新页面，而非给导体棒页面加第 4 种模式

导体棒页面的既有需求写明「三种驱动模式共用统一物理引擎，仅外力取值不同」，而磁铁-线圈的驱动量是位置而非外力，塞入会破坏该需求语义。独立页面同时避免与既有页面争同一组关键词。

替代方案：并入现有页面。已否决。

名称策略：`demos.json` 的 `name` 取短名「磁铁插入/拔出线圈实验」，页面内 `useSEO` 的 title 用完整名「电磁感应-磁铁插入/拔出线圈实验」。原因是 `name` 同时喂给 Dashboard 三列网格卡片标题，长名会让卡片高度与其他卡片不一致；长尾关键词放在 title/description 更合适。slug 取 `magnet-coil-induction`。

### 2. 脚本时间轴而非手动拖拽

磁铁位置是时间的给定函数，帧序列可直接喂给 `useSimulation`，无需自建 pointer 事件与实时状态。拖拽方案会让速度抖动传导到电动势曲线，且难以演示「停留阶段 ε = 0」这一关键格。

主时间轴四阶段（插入 → 停留 → 拔出 → 停留），另设「一次穿过」预设。阶段时长由 `z0`、`v`、`holdTime` 派生，总时长 = 2·z0/v + 2·holdTime，帧数固定 800 均分。

替代方案：拖拽；拖拽与脚本并存。均已否决（成本与可复现性）。

### 3. 准静态处理，忽略线圈自感

真实实验线圈的 τ_L = L/R 在 1 ms 至 20 ms 量级，而磁铁穿越时间在数百毫秒量级，二者相差一到两个数量级，因此准静态在本场景下是正确物理而非简化妥协。

要让 RL 拖尾肉眼可见，需要 L/R ≈ 0.1 s，即 0.5 H 量级的铁芯扼流圈，那已不是演示中的实验对象。既有规格禁止为观感篡改物理量，故不采用。

呈现方式：L 与 τ_L 作为参考常量单行小字置于讲解区下方，注明「远小于穿越时间，故按准静态处理」，符合 `demo-workspace-layout` 对恒定派生量的呈现规则。

### 4. 冲击电流计采用欠阻尼弹道式二阶系统

三个候选方案的实际后果：

```
                   θ ∝ I（瞬时）      θ ∝ 累计电荷       弹道式 ODE
峰值偏角正比于       速度 v            总量 Q（对）       总量 Q（近似，对）
撤出后指针           归零              停在最大值（假）    回摆衰减至零（对）
能否演示 Q 与快慢无关  不能（反向误导）   能，但机制是假的    能，机制也是对的
```

`θ ∝ I` 会让「快插偏角大」，与冲击电流计的真实结论相反，属于演示错误结论，排除；`θ ∝ q` 峰值对但撤出后不回摆，学生可直接看出不物理，排除。

采用方程：θ'' + 2ζω_n θ' + ω_n² θ = k·I(t)，取 ω_n = 2π/2.5 ≈ 2.513 rad/s、ζ = 0.1，k 为仪器灵敏度常数（校准使默认参数下插入行程峰值偏角约 25°）。k 是真实的仪器参数，不属于篡改物理量。

数值积分用 RK4，步长 `stepDt = min(sampleDt/10, T_n/400)`，在每个采样帧区间内子步推进，保证 ω_n 周期内至少有约 400 个积分点。这里对指针状态做数值积分是允许的——规格禁止的是用数值积分求解回路电流。

### 5. 幽灵曲线采用同图低透明度叠加

同一张 ε(t)/θ(t) 图上叠加上一档速度的曲线，比并排双图更省画布高度，也更容易看出「峰值差很多、总面积差不多」。幽灵来源：用户切换速度档后重新播放时，将上一档的帧序列快照保存；首次播放无快照则不渲染，不出现空占位。

替代方案：并排双图（画布高度不足）、差值曲线（对高中场景过抽象）。均已否决。

### 6. 物理量与默认参数取值

磁矩 m 与线圈半径 a 决定量级。取 μ0 = 4π×10⁻⁷，默认 N = 200、a = 0.02 m、R = 2 Ω、m = 0.5 A·m²、z0 = 0.15 m、v = 0.3 m/s，可得到：

```
Φ(0)   ≈ 1.6×10⁻⁵ Wb（单匝），磁链 NΦ ≈ 3.1×10⁻³ Wb
|dΦ/dz| 在 z = a/2 处取极大 ≈ 6.7×10⁻⁴ Wb/m
ε 峰值 ≈ N·|dΦ/dz|·v ≈ 40 mV，I 峰值 ≈ 20 mA
q（插入一段）≈ N·ΔΦ/R ≈ 1.6 mC，插入+拔出 ≈ 3.1 mC
```

这些值落在真实小磁铁 + 教学线圈 + 冲击电流计的合理区间，无需缩放即可显示。

注意 `|dΦ/dz|` 在 z = a/2 处取极大，故 ε 峰值出现在磁铁尚未到达中心的位置，而在 z = 0 处 dΦ/dz = 0、ε = 0。这正是页面要讲的重点，图表上必须能看出 ε 的峰在 Φ 的峰之前。

### 7. 帧结构与读数分层

帧结构 `{ t, phase, z, v, phi, fluxLinkage, emf, current, lorentz, charge, heat, theta }`，全部由解析式得到，无累积误差。

KPI 条（4–6 项，逐帧变化）：Φ、ε、I、θ、q。
参考常量单行小字：N、a、R、m、ΔΦ_total、Q_total、L、τ_L。
侧栏只放：播放/重置、时间轴滑块、速度滑块、预设（标准 / 一次穿过 / 小线圈 / 大电阻）、对照开关。

### 8. 站点地图改为构建前生成的派生产物

生成器 `scripts/gen-sitemap.js` 读取 `src/lib/demos.json`，输出首页与全部演示路由，写入 `public/sitemap.xml`（仓库内跟踪，`dist` 已被忽略，故必须落在 `public/` 才能随构建进入产物）。在 `package.json` 中新增 `sitemap` 脚本，并把生成置于 `vite build` 之前，使 `build` 与 `build:prerender` 都自动产出站点地图；CI 执行的是 `build:prerender`，工作流无需改动。

候选方案与取舍：

```
              构建前写 public/         Vite 插件 closeBundle 写 dist/     手工维护
  产物覆盖      dist 自动复制           直接写产物                        需人工
  dev 预览      有                      无                                有
  仓库可见性    生成物可提交、可 diff     不提交                            人工
  校验能力      可加 --check 对比         无源文件可对比                     无
```

插件方案在 `vite.config.ts` 里塞逻辑，且没有仓库内文件可做一致性校验；手工维护正是本次要消除的问题。选择构建前写入 `public/`。

`lastmod` 取值：用 `git log -1 --format=%cI -- src/lib/demos.json` 获得元数据的最近提交时间，全部条目共用该值——元数据变则站点地图变，语义自洽且不会每次构建都产生 diff。取不到时（如 CI 浅克隆）直接省略 `lastmod` 字段，因为该字段在 sitemap 协议中可选，写当前时间会让每次构建都产生无意义变更。

`--check` 模式：在内存中生成期望内容并与仓库内文件逐字比较，不一致时打印差异条目并以非零码退出，使「站点地图与元数据一致」成为可自动断言的条件，无需启动浏览器。

`.trae/rules/learn.md` 中「新增实验需同步更新 sitemap.xml」的规则在生成方案下自动满足，无需改动规则文件。

## Risks / Trade-offs

- [弹道近似误差：脉冲时长与指针周期之比约 0.2，峰值偏角与电荷的正比关系有肉眼级偏差] → 将「峰值偏角」与「本段累计电荷」并排放在 KPI 条，使近似误差自身可见；原理卡注明该近似的前提。
- [固定 800 帧在高速档下单个采样间隔可能跨过 ε 峰值] → 采样点按阶段等分并在峰值附近加密，或对 ε 曲线在相邻帧间做线性插值绘制。
- [长标题导致 Dashboard 卡片高度不一致] → `demos.json` 用短名，完整名只进 SEO title。
- [站点地图成为生成物后，若开发者只运行 `npm run dev` 而不构建，仓库内文件可能滞后于元数据] → 提供 `--check` 模式并纳入交付验证，使滞后可被发现而非静默存在。
- [生成器与 `demos.json` 结构耦合，元数据新增必填字段时脚本需同步] → 生成器只读取 `path` 字段，并对缺失或格式异常的路径直接失败报错，避免静默产出错误站点地图。
- [新路由自动进入布局验证，若 KPI 项超 6 或侧栏高于画布列，验证会失败] → 严格按第 7 条分层，交付前运行 `npm run verify:layout`。
- [指针参数固定不可调，可能与「所有参数可调」的直觉不符] → 在原理卡说明指针周期与阻尼比属于仪器属性，不随实验参数改变。
