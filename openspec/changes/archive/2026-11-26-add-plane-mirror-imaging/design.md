# Design

## Context

站点已有四个光学演示（`air-water-refraction`、`convex-lens`、`concave-lens`、`eye-simulation`），它们都基于「物距 → 解析求解 → 绘制光路」这一套模式，其中 `ConvexLensSim` 已经实现了「实线光路 + 虚线反向延长线 + 虚像」的完整视觉语言。本次新增的是平面镜成像，动机见 proposal.md 的 Why。

现有可复用基建：

- `useSVGScene`：挂载时初始化 svg.js 场景，后续由 demo 自行重绘。
- 共享组件：`DemoPage`、`SimulationCanvas`、`DemoSidebar`、`KpiBar`、`ParamSlider`、`DemoControls`、`CanvasLegend`、`PrincipleCard`。
- 语义色：`palette.ray`（光线实线）、`palette.reference`（法线与虚线参考线）、`palette.object`（物体主体）均已存在，无需新增。
- 物理内核目录：`src/lib/physics/` 已有 `lens.ts`、`refraction.ts` 等纯函数模块，可沿用「纯函数内核 + 演示层绘制」的拆分。
- 路由与派生资源：`scripts/prerender.js`、`scripts/gen-sitemap.js`、`scripts/verify-layout.mjs` 均从 `demos.json` 派生，新条目自动纳入，无需改脚本。

约束来自既有规格：`demo-workspace-layout` 要求侧栏只放控制、KPI 条 4–6 项只放逐帧变化量、恒定派生量单行小字；`demo-canvas-legend` 要求图例在画布下方正常文档流，不得覆盖画布。

## Goals / Non-Goals

**Goals:**

- 用单一几何内核（`src/lib/physics/planeMirror.ts`）产出一份「镜像变换 + 反射光路」结果，场景、读数、光线全部从同一结果读取，保证画面与读数自洽。
- 让「物距 = 像距、物像连线垂直于镜面」这一对称关系在画面上可直接量读，而非只靠文字结论。
- 支持任意镜面倾角下的对称变换，使镜面旋转不引入特例分支。
- 交互以拖拽为主，无时间轴，与既有四个光学演示的交互形态区分。

**Non-Goals:**

- 不实现光屏承接实验（虚像无法承接这一结论用文字与挡板实验呈现即可，单独引入光屏会额外增加一个交互对象）。
- 不实现多次反射（两镜夹角成像、万花尺）与潜望镜的完整光路。
- 不实现镜面尺寸、镀膜、透射等真实镜面属性。
- 不实现作图题的自动判分。

## Decisions

### 1. 独立新页面，slug 取 `plane-mirror-imaging`

既有四个光学演示都各自独立成页，平面镜成像的物理内核（镜像变换）与透镜（高斯成像公式）、折射（斯涅尔定律）没有任何共用计算，塞进现有页面只会破坏其需求语义。

名称策略沿用既有约定：`demos.json` 的 `name` 取短名「平面镜成像实验」，页面内 `useSEO` 的 title 用完整名。原因是 `name` 同时喂给 Dashboard 三列网格卡片标题，长名会让卡片高度与其他卡片不一致。

### 2. 拖拽交互，不引入时间轴

平面镜成像没有随时间演化的物理量：像的位置完全由物体的瞬时位置决定，不存在「播放」这一维度。`magnet-coil-induction` 采用脚本时间轴是因为磁通量需要以时间积分；这里相反，拖拽是唯一自然的交互。

因此不接入 `useSimulation`，改为在画布上监听 pointer 事件，拖动时逐帧调用几何内核重绘。

```
              拖拽实时重算          脚本时间轴 + useSimulation
  物理量       瞬时几何（无积分）    需要 ∫dt 的累积量
  交互成本     低（pointer 直接映射） 中（需预计算帧序列）
  适用场景     平面镜、杠杆          磁铁-线圈、落液
```

### 3. 镜像变换用向量投影，而非坐标轴翻转

像点 = 物点关于镜面所在直线的反射点。实现为：把镜面方向取单位向量 `d`，法线取单位向量 `n`，物点 `P` 的像点 `P' = P - 2·((P - A)·n)·n`，其中 `A` 是镜面上一点。该式对任意镜面倾角都成立，无需 `if (镜面水平)` 之类的特例分支，也就不会出现「旋转后像位置错乱」这类只在某个角度下暴露的 bug。

替代方案：在镜面坐标系里做 y 轴翻转再变换回世界坐标。数学上等价，但需要额外的旋转矩阵与逆变换，代码更长且更容易出错。

所有几何量（物距、像距、入射角、反射角）都由这一变换派生，不在绘制层二次计算，避免两处公式漂移。

### 4. 光路取「物体底部与顶部两点」，每点一条入射光线

两条入射光线分别从物体两端射向镜面上的指定入射点，反射光线按反射定律绘制，反射光线的反向延长线交于像上对应点。之所以取两个点而非一条：单条光线只能说明「反射角 = 入射角」，两条光线的延长线相交才能说明「像是一个点，且该点是所有反射光线反向延长线的公共交点」，这正是虚像定义的几何依据。

入射点位置随物体位置移动而保持相对比例，避免用户拖动物体后光线飞出画布。

绘制约定沿用 `ConvexLensSim`：实线画入射与反射光线，虚线画反向延长线，虚线颜色取 `palette.reference`，像的轮廓取虚线。

### 5. 镜面旋转与镜后挡板作为两个独立开关

镜面倾角用 `ParamSlider` 控制，挡板用 `DemoControls` 里的开关控制。二者互不影响，都只改输入参数后重绘，不引入额外状态机。

挡板在镜后以半透明矩形呈现，放在像与镜面之间靠后位置，使「像仍然可见」在视觉上有说服力——挡板确实画在镜后，但像不受影响，因为镜后本无实际光线。

### 6. 读数分层

KPI 条（6 项，全部随拖拽或旋转变化）：物距 u、像距 v、物高 h、像高 h′、入射角 θᵢ、反射角 θᵣ。

恒定结论单行小字：放大率恒为 1、像距恒等于物距、物像连线垂直于镜面、像为虚像。

侧栏只放：镜面倾角滑块、光线显示开关、对称辅助线开关、镜后挡板开关、重置。

注意 u 与 v 的读数恒相等、h 与 h′ 恒相等，这是平面镜的物理结论本身，而非冗余：两个读数并排显示，学生才能亲眼看到它们始终相同。这一点与「同一物理量不重复出现」的规则不冲突——u 与 v 是不同的物理量，只是数值恒等。

### 7. 单位与坐标系

画布 `viewBox` 取 800×500，镜面为过画面中心的可旋转直线，默认竖直放置。显示单位取 cm，1 cm = 20 px，使物距读数落在 5–20 cm 的教材常见区间。物高以 cm 显示，与物距共用同一比例尺。

## Risks / Trade-offs

- [拖拽在触摸设备与鼠标上的事件差异] → 统一使用 pointer 事件（`pointerdown` / `pointermove` / `pointerup`）并在拖动时调用 `setPointerCapture`，避免手指移出画布后丢失拖动。
- [旋转镜面后光路可能飞出画布或自交] → 入射点按物体两端到镜面的相对位置取，且在镜面旋转时同步限制入射点落在镜面可视段内；超出时截断光线而不改变其方向。
- [KPI 条 6 项已到上限，后续若想加读数会触发布局验证失败] → 本次严格控制在 6 项，其余结论一律进单行小字。
- [预渲染阶段无交互，画面必须是初始状态的静态可渲染结果] → 初始状态即给出默认物体位置与完整光路，`DemoPage` 挂载后置 `__PRERENDER_READY__`，与既有演示一致。
- [虚线与实线在浅色画布上对比度不足] → 像与延长线统一用 `palette.reference`，线宽与实线相同，仅线型不同，保证在灰度打印或色弱视角下仍可区分。
