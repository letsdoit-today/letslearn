# Design

## Context

现有 6 个 demo 均为「随时间演化」（球体落液）或「手动拖拽单变量」（斜面摩擦），共享一套 `palette` 语义色、`DemoPage` / `SimulationCanvas` / `ParamSlider` / `DataPanel` / `PrincipleCard` 组件与 `useSVGScene`（仅挂载时初始化一次，后续由 demo 自行驱动重绘）。

约束：
- 力矩平衡是静态概念，引入时间轴会稀释「配平」这一核心体验。
- 但纯静态画面缺乏反馈感，横梁需要「不平衡时倾斜」的动感。
- 力臂误区（力臂 ≠ 支点到作用点距离）是本实验最大教学价值，必须可视化。
- 路由与预渲染由 `src/lib/demos.json` 单一数据源派生（`scripts/prerender.js`），无需改构建配置。

## Goals / Non-Goals

**Goals:**

- 用一个页面同时承载「力矩定义（含倾斜施力）」与「杠杆平衡条件」两个考点。
- 参数改动后画面与数据面板即时更新；横梁倾角平滑追随，不跳变。
- 复用现有 `palette` 语义色与侧栏组件，保持全站视觉一致。
- 物理计算与几何绘制解耦，纯函数可独立验证。

**Non-Goals:**

- 不做真实动力学积分（无角加速度、无摆动衰减），不引入 `useSimulation` 与时间轴。
- 不做杠杆两端物体的质量/体积建模，`F1`、`F2` 直接作为力值输入。
- 不做多支点、复合杠杆、滑轮组等扩展形态。

## Decisions

### D1：静态配平 + 缓动倾斜（混合形态 C）

以 `useState` 驱动参数，不引入时间轴；横梁倾角由目标值经 RAF 插值追随。

- 备选 A（纯静态）：最省事，但画面无反馈，不平衡只能靠数字看出来。
- 备选 B（动态旋转积分）：最有动感，但时间轴会让人分心去等动画，且平衡条件这个重点被稀释。
- 选择 C 的理由：数字即时更新（教学聚焦）+ 倾斜缓动（视觉反馈），且无需积分逻辑。

### D2：倾角仅作视觉反馈，不参与力矩运算

滑块定义的水平距离 `L` 与角度 `θ` 直接决定力矩，横梁倾斜后**不重算**力臂。

- 备选：倾斜后按 `cos(倾角)` 修正力臂，更「真实」。
- 否决理由：数字会随倾斜抖动、形成自我反馈，平衡判据不稳定，且平衡时倾角为 0 已自洽。教学口径需要干净的 `M = F·L·sinθ`。

### D3：θ 一次到位（有效力臂 = L·sinθ）

θ 定义为**力与横梁的夹角**，取值 `[30°, 90°]`，90° 表示垂直施力。

- 取 `[30°, 90°]` 而非 `[0°, 180°]`：避免力方向跨越支点导致的力矩符号反转，保证 `arm = L·sinθ ≥ 0` 恒成立，教学画面不产生歧义。
- 有效力臂按「支点到力的作用线的垂距」绘制，而非连到作用点——这是打掉误区的关键一笔。

### D4：整组旋转，θ 相对横梁定义

横梁、作用点、力箭头、力臂虚线放入同一个旋转 group，整体按倾角旋转；支点三角、地面、力矩弧形箭头保持静止。

- 理由：θ 相对横梁定义时，`arm = L·sinθ` 在旋转下不变，与 D2 完全自洽。
- 代价：力箭头随横梁倾斜 8°，与「重力方向恒定」略有出入；8° 幅度下视觉可接受，且避免「箭头不动但作用点动」造成的错位。

### D5：RAF 插值而非 CSS transition

`speed = 0.15` 的逐帧逼近（`current += (target - current) * 0.15`），差值收敛到 0.05° 内停止循环。

- 否决 CSS transition：`useSVGScene` 中元素通过 svg.js 设置 `transform` 属性，CSS 过渡对该属性不可靠，且旋转 group 需要每帧重算子元素几何。

### D6：绘制分层与几何口径

以支点为局部原点、x 沿横梁向右、y 向下：

```
P（作用点）= (L_px, 0)          // 横梁下边缘，保证 P·u 精确等于 L_px·cosθ
u（力方向）= (cosθ, sinθ)       // θ 由横梁转向下方量取
F（垂足）  = P - (P·u)·u
           = (L_px·sin²θ, -L_px·sinθ·cosθ)
|OF|      = L_px·sinθ           // 即有效力臂
```

四层：结构（横梁/支点/地面）→ 力臂（`O→F` 虚线 + 双端标记 + 垂足直角标记）→ 力（`P→P+u·arrowLen` 箭头 + 作用线虚线）→ 力矩（支点两侧弧形箭头）。

### D7：倾角映射与平衡判据

```
ratio  = |net| / (m1 + m2)                          // net = m2 - m1
balanced = ratio < 1%                               // 相对判据，避免滑块步进导致永不相等
tilt   = balanced ? 0
       : sign(net) * (2° + 6° * min(ratio, 1))      // 不平衡时恒有 2°~8° 的可见倾角
leverType: arm1 > arm2 → 省力；arm1 < arm2 → 费力；否则 等臂
```

- `tilt` 用相对比值而非绝对值：不同力量级下倾斜幅度一致，避免大力矩时横梁翻出画面。
- 设 2° 下限而非纯线性：纯线性在常见配平失衡下只有 1°~3°，肉眼几乎不可见；下限保证「只要不平衡就一定看得出来」，上限 8° 保证横梁不翻出画面。
- 相对平衡判据：滑块为离散步进，绝对 `ε` 在不同量级下松紧不一。

### D8：预设按钮为纯数据

四组预设（等臂天平 / 省力杠杆 / 费力杠杆 / 斜向施力对比）以常量表定义在物理层，点击即批量设置 6 个滑块。第四组刻意设成「两侧 F、L 相同、仅 θ 不同」，用来直观展示 θ 对力矩的影响。

## Risks / Trade-offs

- [θ 相对横梁定义，力箭头随倾斜旋转 8°，与重力恒向略有出入] → 幅度控制在 8° 以内；倾角本身只是「往哪边倒」的提示，不作为定量依据。
- [旋转 group 内的文字（力值、力臂标注）随倾斜旋转 8°] → 幅度小，可读性不受影响；如需绝对水平，需把文字拆到独立静止 group 并按旋转后坐标重定位，成本明显上升，故不做。
- [相对平衡判据 1% 让「接近平衡」也显示为平衡] → 滑块步进本身无法精确配平（如 `L` 步长 0.05 m），1% 是必要容差；数据面板同时展示净力矩数值，精确值仍可见。
- [θ=90° 时垂足与作用点重合，直角标记退化] → 这正是「力臂 = 水平距离」的正确表达，保留该形态作为默认视觉。
- [新增 demo 需同步 4 处注册点，易漏] → 任务中单列「注册」一项，并在 `npm run build` 后走查首页与详情页可访问。
