# Design

## Context

见 `proposal.md - Why`。当前外壳的关键结构（`src/components/Layout.tsx`）：

```
div.min-h-screen.flex                     <- 高度 = 内容高度，body 负责滚动
  aside.md:static.w-64 / md:w-0           <- 随文档流移动，所以会滚走
  main.flex-1.flex.flex-col
    header.sticky.top-0.z-10              <- 相对 body 滚动，实际压住内容顶部 56px
    div.flex-1.p-3.sm:p-6.overflow-auto    <- 父高为 auto，永不成为滚动容器
```

`DemoPage` 工作台行是 `flex flex-col lg:flex-row gap-6`，侧栏 `w-full lg:w-80`。

实测（puppeteer，1024×768，导航展开）：

| 视口 | 画布容器 | svg 绘制区 | 侧栏 |
|---|---|---|---|
| 1024 | 294 × 409 | 294 × 184 | 320 宽，589 高 |
| 1279 | — | 294 × 184（行布局，宽度不随视口增长） | 320 宽 |
| 1366 | 636 × 528 | 636 × 397 | 320 宽 |

1024 与 1279 的画布绘制宽度完全相同：`lg` 断点一旦触发，侧栏 320px 与导航 256px 共同吃掉全部增量，画布被锁死在 294px。这是「侧栏回落」必须解决的问题。

## Goals / Non-Goals

**Goals:**

- 导航在桌面视口固定，长页面滚动时始终可用
- 单一滚动容器，消除 body 滚动与内容区滚动的歧义
- 1024–1279px 下画布拿回完整内容宽度（从 294px 到 638–893px）
- 用校验脚本固化断点与滚动契约，防止回归

**Non-Goals:**

- 不引入容器查询（`@container`）以平滑断点——需要额外插件，先用视口断点加脚本兜底
- 不改移动端抽屉的交互形态，只保证它在新的滚动契约下仍可用
- 不调整侧栏自身宽度（仍为 320px / `lg:w-80`），也不调整 KPI 项数
- 不处理 1280px 断点两侧的画布尺寸跳变（已知代价，见风险）

## Decisions

### 固定导航：外层 `h-dvh overflow-hidden`，而非把 `<aside>` 改成 `fixed`

采用：外层 `div.h-dvh.overflow-hidden.flex`，`<aside>` 保持 `md:static`，内容区 `flex-1.overflow-auto` 因父级有了确定高度而真正成为滚动容器。

- 备选：`<aside>` 改 `md:fixed` + `<main>` 加 `md:ml-64`。需要在 JS 与 CSS 两处同步维护 256px 宽度，且折叠动画（`transition-all` + `md:w-0`）需要重写为 `translate`，改动面更大。
- 备选：`<aside>` 改 `md:sticky md:top-0 md:h-screen`。依赖 body 滚动，`sticky` 在内容区 `overflow-auto` 存在时的行为容易出错，且未解决「body 滚动 vs 内容区滚动」的歧义。
- 选择理由：一处改动同时解决两个问题——`<aside>` 不滚动，且滚动容器唯一。动画逻辑完全不变。

高度基准用 `h-dvh`（`100dvh`）而非 `h-screen`（`100vh`）：移动端工具栏收起时 `100vh` 会大于可视高度，导致底部内容被遮挡。项目 Tailwind 3.4 已内置 `h-dvh`，无需插件。

### 断点：`lg` → `xl`（1024 → 1280）

- 备选：保留 1024 行布局、把侧栏从 320 缩到 240。1024 下画布可从 294 升到 374，仍小于手机宽度，且牺牲滑块精度，否决。
- 备选：1024–1279 区间让侧栏浮于画布右侧（`absolute`）。会遮住画布，与上一轮「不遮挡」的结论冲突，否决。
- 备选：把断点提到 1330 以消除 1366 的跳变。会让 1366 本身失去同屏能力（`demo-workspace-layout` 的核心场景），否决。
- 选择 1280：`xl` 是现成断点，零新增配置；1024–1279 属笔记本与小屏台式机，纵向排列下画布反而更大，体验优于当前的 294px。

断点两侧的画布尺寸：

```
1279 (纵向)  画布 893 x 558     1280 (行)  画布 550 x 344
```

跨度 38%，属已知代价。

### 画布高度上限常数：`9rem` → `12rem`

导航固定后 header 不再与画布重叠，画布顶边从「被 header 覆盖」变为「在 header 之下 56px 处」，同屏预算净减少 56px。折叠导航时画布自然高度最大（1236 宽 → 772 高），必然被 clamp，按 1366×768 折叠导航推算：

```
56(header) + 16(容器内边距) + 24(卡片内边距) + 画布 + 12(间距) + 52(KPI) + 16(容器内边距)
= 176 + 画布
768 - 176 = 592  ->  取 12rem = 192 作为上限，768 - 192 = 576，留 16px 余量
```

若图注行（`refactor-canvas-legend`）已落地，需再减去图注高度，上限进一步收紧；两处改动须串行，后实施者重算。

### 校验脚本：断言作用域随断点变化

`scripts/verify-layout.mjs` 三处调整：

1. 视口矩阵补入 `1024×768`，与 1366、1920 并列
2. 侧栏底边断言仅在 `width ≥ 1280` 生效；1024–1279 改断言「画布底边 + KPI 底边在视口内」且侧栏位于画布列下方（侧栏 `top` > 画布 `bottom`）
3. 横向溢出改测内容区容器的 `scrollWidth / clientWidth`，因为外层 `overflow-hidden` 后 `document.body.scrollWidth` 不再反映溢出

另外 `workspaceTop` 的计算需从 `getBoundingClientRect().top + window.scrollY` 改为相对滚动容器的偏移，否则滚动容器切换后该值恒等于视口坐标，日志失真（该值仅用于诊断输出，不影响断言）。

## Risks / Trade-offs

- [1280 断点处画布宽度从 893 骤降到 550] → 已知代价；用「断点切换时画布宽度不小于切换前一半」的断言兜住下限，避免将来把侧栏或断点改得更糟。
- [折叠导航时 1366×768 的画布被 clamp 到 576，小于自然高度 772] → 画布变小但仍完整同屏，符合「同屏优先于大画布」的既有取舍。
- [`h-dvh` 在旧浏览器不支持] → Tailwind 3.4 已内置；项目无 IE 支持诉求，且旧浏览器会回退为 `auto`，表现为外壳高度不确定，属可接受降级。
- [滚动容器从 body 换到内容区，可能影响 `scrollIntoView` 与锚点行为] → 校验脚本已依赖 `scrollIntoView`，需在改动后立即跑全量校验；`overflow-hidden` 外层下 `scrollIntoView` 仍会作用于内容区容器。
- [图注行与本次改动都改 `verify-layout.mjs`] → 串行实施，后实施者负责最终常数与断言合并。
