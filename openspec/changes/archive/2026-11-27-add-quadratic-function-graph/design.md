# Design

## Context

见 `proposal.md` 的 Why 与 `specs/quadratic-function-graph/spec.md` 的 requirements。这里只记录实现层面的现状与约束。

- 站点既有 14 个演示中，时间驱动型（`FallingBall`、`PendulumOscillation`、`MagnetCoilInduction`、`PhotosynthesisRespiration`）用 `useSimulation` + `DemoControls`；参数驱动型（`SolubilityCurve`、`PlaneMirror`、`MendelInheritance`、`LeverBalance`、`EyeSim`）只有 `ParamSlider`，无播放控件。本条属于后者。
- 参数驱动型的画布更新方式统一为：`useSVGScene` 一次性创建全部元素并把引用存入 `snapRef`，参数变化时在 `useEffect` 里只更新既有元素的属性，不重建 DOM。
- 画布 `viewBox` 统一为 `0 0 800 500`，`SimulationCanvas` 负责等比缩放；`verify:layout` 会在 1024×768 / 1366×768 / 1920×1080 及折叠导航下校验布局。
- `palette.ts` 目前没有数学色区；`demoIcons.tsx` 的 `iconMap` 无数学条目，兜底为 `FlaskConical`。

## Goals / Non-Goals

**Goals**

- 让「`b`、`c` 只平移、`a` 改形状」这个结论在画布上可被直接比对，而不是靠口诀记忆。
- 在 800×500 的画布内，让 `a ∈ [-2, 2] \ {0}`、`b ∈ [-3, 3]`、`c ∈ [-5, 5]` 的全部组合都能看到顶点与对称轴。
- 保持与既有参数驱动型演示同构的组件与更新方式，不新增依赖。

**Non-Goals**（设计层面，与 proposal 的范围排除不重复）

- 不做配方法逐步变形动画，不显示顶点式与一般式的逐项换算过程。
- 不做坐标网格（只画两条轴与刻度），避免与两条曲线争夺视觉层次。
- 不做触摸手势缩放 / 平移坐标系，视野固定。
- 不做 `a` 的连续取值（`a` 走 0.5 步长），换取滑块吸附与读数整齐。

## Decisions

### 1. 坐标映射刻意非等比：`x` 64 px/单位，`y` 20 px/单位

绘图区取 `PLOT = { left: 80, right: 720, top: 44, bottom: 444 }`，即 640 × 400 px，原点落在 `(400, 244)`。

```
   x ∈ [-5, 5]   →  640 px  →  64 px / 单位
   y ∈ [-10, 10] →  400 px  →  20 px / 单位
```

**为什么必须非等比**：顶点纵坐标 `k = c - b²/(4a)` 里带 `b²`，量级远大于横坐标 `h = -b/(2a)`。实测该参数区间的取值范围：

```
   h ∈ [-3.0, 3.0]      (a = ±0.5, b = ∓3 时取到)
   k ∈ [-9.5, 9.5]      (a = 0.5, b = -3, c = -5 时取到 -9.5)
```

若坚持等比，800×500 的画布（比例 1.6 : 1）要装下 `k = ±9.5`，横轴只能装 `±2.97`，`h = 3` 的顶点会贴边甚至出界；反过来让横轴装 `±5`，纵轴只剩 `±3.1`，`c = 5` 的曲线整段画不出来。**非等比是参数区间决定的，不是排版偷懒。**

**关键前提**：两条曲线走同一组线性映射，因此 `a` 相同时它们在屏幕上仍然全等。非等比只会让抛物线整体「看起来更扁」，不影响「`b`、`c` 只造成错位」这一核心观察。这一点是本条演示成立的基础，实施时 MUST 用同一个 `toScreen(x, y)` 函数给两条曲线与所有标注点做映射。

**考虑过的替代方案**：

| 方案 | 问题 |
| --- | --- |
| 等比坐标（64 px/单位，双轴同比例） | 纵轴只到 ±3.1，`c` 与 `k` 的大半取值范围画不出来 |
| 等比但动态缩放视野（跟随顶点） | 视野随参数变化，两条曲线无法稳定比对，恰好摧毁教学主张 |
| 非等比 + 坐标网格 | 网格在非等比下会诱导学生误读斜率，与「形状全等」的观察冲突，故不画网格 |

### 2. 参数范围与步长

| 参数 | 范围 | 步长 | 依据 |
| --- | --- | --- | --- |
| `a` | `[-2, 2]`，排除 0 | 0.5 | 0.5 步长让 `a` 取 `±0.5 / ±1 / ±1.5 / ±2`，形状差异肉眼可辨；整数步长会让 `a=±1` 占太多档位 |
| `b` | `[-3, 3]` | 1 | 与 `a` 的最小绝对值 0.5 配合，使 `|h| ≤ 3`，稳稳落在横轴 `±5` 内 |
| `c` | `[-5, 5]` | 1 | 纵轴 `±10` 可容纳 `c` 的全部取值，`k` 的极端值 ±9.5 也在界内 |

### 3. `a = 0` 用滑块吸附跳过，不用禁用档位

`Slider` 的 `onValueChange` 拿到原始值后立刻吸附：

```
raw === 0  →  取方向：raw < prev ? -0.5 : +0.5
```

方向由**原始值与上一个有效值的大小关系**决定，而不是取 `prev` 的符号。从左往右拖命中 0（`prev = -0.5`）时 `raw > prev`，跳到 `+0.5`；从右往左拖命中 0（`prev = +0.5`）时 `raw < prev`，跳到 `-0.5`。这样拖动的手感是「卡一下越过去」，而不是「卡住不动」——后者会让学生以为滑块坏了。

**为什么不按 `prev` 的符号取方向**：`prev = -0.5` 向右越过 0 时，若按符号跳 `-0.5`，取值会被弹回原位，滑块在 0 处永久卡死；键盘方向键逐档移动时尤其明显（每次按右方向键都回到 `-0.5`）。符号法只对「从远端一路拖到 0」的极端场景碰巧成立，不可用。

**考虑过的替代方案**：

| 方案 | 问题 |
| --- | --- |
| 把 `a=0` 从取值集合里删掉（`[-2,-0.5] ∪ [0.5,2]`） | `Slider` 不支持分段区间，需自造控件，偏离共享组件 |
| 允许 `a=0` 并显示一次函数 | 超出本条范围，且 `h = -b/(2a)` 除零，顶点与对称轴全部失效 |
| 命中 0 时停在最近的非零档 | 学生拖到 0 附近会发现「拖不动」，手感更差 |

### 4. 判别式三态用形状区分，不靠位置错开

`Δ = 0` 时顶点恰好落在 `x` 轴上，顶点标记与交点标记会同心。解法是让两者的**形状**不同：

```
   Δ > 0   顶点 = 实心圆 r=5     交点 = 两个实心小圆 r=4
   Δ = 0   顶点 = 实心圆 r=5     交点 = 空心环 r=9（描边不填充，套在顶点外圈）
   Δ < 0   顶点 = 实心圆 r=5     交点 = 不绘制，KPI 标注「无实根」
```

`Δ = 0` 的空心环半径大于顶点圆，形成「靶心」构图，读作「交点就是顶点本身」，不需要额外箭头或引线。图例第 5 条写「与 x 轴交点（有实根时）」，避免 `Δ < 0` 时图例指向画布上不存在的元素。

### 5. 顶点标注避让规则

顶点坐标文字默认放在顶点右上方 `(+12, -12)`，按三条规则修正：

1. 文字右边界超出绘图区右边界 → 翻到左上方 `(-12, -12)`，`text-anchor` 改为 `end`。
2. 顶点纵坐标换算后的 `y` 距 `x` 轴不足 18 px → 竖直偏移从 `-12` 改为 `+20`（翻到下方），避开 `x` 轴刻度文字。
3. 顶点在上半区（`y < 244`）时，若上方偏移会越过绘图区上边界 → 同样翻到下方。

这三条只影响标注位置，不影响曲线本身。端到端断言会遍历五个预设 + 四个极端组合逐一检查文本包围盒无交叠。

### 6. 曲线裁剪交给 `clipPath`，采样不截断

抛物线按 `x ∈ [-5, 5]` 均匀采样 161 个点（步长 0.0625），拼成 `path` 的 `d`，再给两条曲线套一个 `clipPath` 限定在 `PLOT` 矩形内。**不对采样点做截断**——截断会让 `a = 2` 的陡峭抛物线在出界处出现「折线拐角」，而 `clipPath` 是干净的直角裁切。

### 7. 参数驱动、无 `useSimulation`

不引入 `useSimulation` 与 `DemoControls`。`a`、`b`、`c` 三个 `useState` 直接构成唯一状态源，`useEffect` 依赖三者更新画布属性。这与 `SolubilityCurve` 的形态一致，也让「同一组参数两次进入必然一致」成为天然性质，不需要额外断言。

### 8. 语义色与图标

`palette.ts` 新增数学色区（色值沿用 Tailwind 默认色阶）：

| 键 | 色值 | 语义 |
| --- | --- | --- |
| `mathCurve` | `#1e293b` slate-800 | 当前曲线 `y = ax² + bx + c` |
| `mathReference` | `#94a3b8` slate-400 | 参考曲线 `y = ax²`（虚线） |
| `mathAxis` | `#94a3b8` slate-400 | 对称轴（虚线） |
| `mathVertex` | `#ea580c` orange-600 | 顶点标记与标注 |
| `mathRoot` | `#2563eb` blue-600 | 与 `x` 轴交点 |

`mathCurve` 与既有 `palette.curve` 同值但独立命名：`curve` 是化学溶解度曲线的语义，若复用会让「颜色即语义」的约定失效。

图标用 `FunctionSquare`（已核实 `lucide-react` 中存在该导出），语义为函数图像，比 `Sigma`（更适合统计求和）与 `TrendingUp`（更适合趋势类）更贴切。

## Risks / Trade-offs

- **[非等比让 `a` 的形状差异在视觉上被压缩]** → 纵轴 20 px/单位，`a` 从 0.5 变到 2 时开口宽窄的变化在屏幕上小于等比视野。缓解：KPI 条直接给出 `a` 的数值与开口方向，参考曲线始终同框提供「同 a 基准」，学生比对的是两条曲线的相对关系而非绝对宽窄。

- **[`c` 较大时曲线顶部被裁掉，学生看不到完整开口]** → 这是 `clipPath` 的必然结果。缓解：`c ∈ [-5, 5]` 而纵轴到 `±10`，只有 `a` 取较大正值且 `|c|` 取较大时才明显裁剪；五个预设全部在界内完整可见。

- **[`Δ = 0` 的空心环可能被误读为「两个点靠在一起」]** → 缓解：空心环半径 9 px 明显大于顶点圆 5 px，形成同心靶环；图例条目文案写「与 x 轴交点（有实根时）」，KPI 的 `Δ` 值为 0 时同时显示「重根」。

- **[顶点标注在极端参数下仍可能与刻度文字交叠]** → 缓解：三条避让规则 + 端到端断言遍历预设与极端组合，逐项检查文本包围盒。

- **[滑块步长 0.5 让 `a` 无法取 `±0.25` 之类的小值]** → 教学上不需要这些中间值；若后续要支持更细的 `a`，只需改步长，坐标视野已留有余量（`|h|` 最大 3，横轴到 5）。

## Migration Plan

纯新增，无数据迁移与回滚需求。若需回退：删除新增的 `src/lib/math/quadratic.ts` 与 `src/demos/QuadraticFunctionGraph.tsx`，回退 `palette.ts`、`demos.json`、`App.tsx`、`demoIcons.tsx`、`ROADMAP.md` 的对应改动即可，既有 14 个演示不受影响。

## Open Questions

- 是否在画布上额外标注「`a` 与 `b` 同号时对称轴在 `y` 轴左侧」这一定性规律。当前 spec 未要求，且该规律属于口诀式总结，与本条「用全等比对代替口诀」的主张略有张力，可留待实施后再判断。
- 图例是否需要第 6 条列出 `y` 轴交点。当前计划图例 5 条，`y` 轴交点已在画布上直接标注 `(0, c)`，暂不单独占图例位。
