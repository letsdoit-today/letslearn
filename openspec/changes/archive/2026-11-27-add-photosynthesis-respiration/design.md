# Design

## Context

参见 proposal.md 的 Why 与 specs/photosynthesis-respiration/spec.md 的 requirement。此处只记录实施所需的技术现状与约束。

站点已有的可复用资产：

- `useSVGScene`：画布元素一次挂载，后续通过 `snapRef` 持有元素引用做增量更新（孟德尔、溶解度等 13 个演示都走这条路径）
- `useSimulation`：以 `frames` 预计算 + `time` 推进的方式驱动播放，提供 `play` / `pause` / `reset` / `setTime`，已有单摆、落液、电磁感应、磁铁线圈四个演示在用
- `DemoControls`：播放 / 暂停 / 重置按钮组，可直接配套 `useSimulation`
- `KpiBar` / `CanvasLegend` / `DemoPage` / `DemoMain` / `DemoSidebar` / `ParamSlider` / `PrincipleCard`：共享布局与读数组件
- `palette.ts`：全站语义色单一来源，已有 `bioDominant` / `bioRecessive` / `bioGamete` / `bioParent` 四条生物色

硬约束（由既有 change 建立并已被 `verify:layout` 固化）：KPI 条 4–6 项只放逐帧变化量、恒定结论单行小字、画布图例不覆盖画布、画布内不得有承载读数的绝对定位浮层、无横向溢出。

## Goals / Non-Goals

**Goals**

- 单一自变量（昼夜时刻）即可完整驱动画面，不出现参数组合爆炸
- 全部画面元素都由同一个计算结果对象派生，杜绝「曲线说净吸收、箭头说净释放」这类自相矛盾
- 暂停态完全冻结，使端到端断言可以逐点比对数值

**Non-Goals**

- 不实现光反应 / 暗反应的内部环节（类囊体、基质、ATP、NADPH、C3/C5），那属于高中且会让画布信息密度失控
- 不引入温度、CO₂ 浓度为第二、第三自变量
- 不复用孟德尔那套棋盘骨架 —— 两者没有共享的数据形状，强行复用只会制造耦合
- 不改造任何既有共享组件；本条不新增基建

## Decisions

### 1. 主变量取昼夜时刻，光照强度为派生量

滑块与时间轴操作的对象是 `t ∈ [0, 24)`，光照强度由日照曲线派生：

```
L(t) = 100 * sin(π * (t - 6) / 12)     6 ≤ t ≤ 18
L(t) = 0                               其他
```

**理由**：`useSimulation` 的时间轴天然是 `t`，播放与拖拽都可直接复用，无需自建时钟；而曲线的横轴仍是 `L`，光补偿点与饱和这两个概念因此完整保留。

**替代方案**：直接拖光照强度 `L`。放弃的原因是那样只能做静态演示，拿不到「夜间净释放、白天净吸收」的昼夜叙事，而后者正是初中段最需要被纠正的认知误区。

### 2. 光合速率用饱和型曲线

```
P(L) = Pmax * L / (L + K)        Pmax = 30，K = 45
R    = 5                         恒定
N(L) = P(L) - R
```

代入后光补偿点解为 `L_c = 9.00%`，对应时刻 **06:21 与 17:39**；正午 `L = 100` 时 `P = 20.69`，距饱和上限 30 仍有余量，饱和趋势清晰可见。

| 时刻 | L | P | R | N |
| --- | --- | --- | --- | --- |
| 06:00 | 0.00 | 0.00 | 5.0 | −5.00 |
| 06:21 | 9.00 | 5.00 | 5.0 | 0.00 |
| 12:00 | 100.00 | 20.69 | 5.0 | +15.69 |
| 17:39 | 9.00 | 5.00 | 5.0 | 0.00 |
| 18:00 | 0.00 | 0.00 | 5.0 | −5.00 |

**替代方案**：`P = Pmax·L²/(L² + K²)`。放弃的原因是该式在 `L = 0` 处导数为零，曲线呈 S 形 —— 极弱光段几乎贴地不起，与「弱光段速率随光强上升、增速明显」的规格相冲突；实测弱光段与强光段的斜率比仅 1.4 倍，饱和趋势读不出来。

**替代方案**：线性 `P = k·L`。放弃的原因是线性没有饱和，强光段与弱光段斜率相同，学生读不出「光照继续增强但光合不再明显加快」这一事实，而这是本条的第二个教学落点。

**替代方案**：分段折线。画布上会多出折点，视觉上像数据不足，不如单条平滑曲线可信。

### 3. 边界只画净交换箭头，细胞内部画过程流

细胞膜上只画 CO₂ 与 O₂ 的**净**方向箭头，箭头长度与粗细编码 `|N|`；`N = 0` 时两侧箭头收成「收支平衡」标记。叶绿体与线粒体之间画有机物与 CO₂ 的流向，表现两过程在同一细胞内耦合。

**理由**：若同时画「光合吸 CO₂ 放 O₂」与「呼吸放 CO₂ 吸 O₂」四组箭头，边界会出现方向相反的箭头互相穿插，视觉上无法分辨净方向，反而遮住了本条的结论。

### 4. 曲线与细胞图上下分屏，不并排

画布 800×500：上半部约 300px 给细胞场景，下半部约 170px 给「光照强度 – 速率」曲线，剩余为标题与间距。

**理由**：曲线横轴需要 0–100 的完整刻度与补偿点标注，并排布置会把宽度压到 380px 以下，刻度标签必然重叠。

**替代方案**：只画细胞不画曲线。放弃的原因是光补偿点就没有可读的载体，只能靠 KPI 上的一个瞬时数字，概念落不下来。

### 5. 播放复用 useSimulation 预计算帧

`compute` 一次性生成 480 帧（`dt = 0.05`，一日 24 单位），每帧携带 `{ t, L, P, R, N }`；`loop: true`，60fps 下约 8 秒走完一天，其中夜间 4 秒。

**理由**：帧序列是纯函数结果，播放不引入随机源；`setTime` 直接映射到帧下标，拖拽即定位。这条同时满足「暂停后画面冻结」与「拖拽不经过中间过程」两个 scenario。

**替代方案**：在 `useEffect` 里自建 `requestAnimationFrame` 累加 `t`。放弃的原因是站点已有四处在用同一套基建，自建会造成第五种时间推进方式，且暂停冻结需要额外处理。

### 6. 粒子流动相位由 t 派生，不用随机数

细胞内的物质流用小圆点沿固定路径移动表示，其位置是 `t` 的纯函数（`phase = (t * k + offset) % 1`），不使用 `Math.random()`，也不使用种子化 PRNG。

**理由**：孟德尔那条因为用 `Math.random()` 导致端到端断言不可执行，最终改用 mulberry32。本条的主时钟本身就是确定的 `t`，粒子相位直接由它派生即可，连 PRNG 都不需要 —— 断言在暂停态逐点比对，播放态只校验方向与单调性。

### 7. 呼吸速率恒定值不进 KPI

呼吸速率全程恒为 5.0，因此不占 KPI 项，而是以曲线上的水平虚线 + 图例条目 + 单行小字三种方式呈现；KPI 只留 5 项随 `t` 变化的量：时刻、光照强度、光合速率、净速率、净流向。

**理由**：与孟德尔那条已立下的口径一致 —— KPI 条只放逐帧变化量。恒定值放进 KPI 会让整条读数条出现一个永远不动的格子，稀释了「读数条反映当前状态」这个语义。

### 8. 语义色新增五条生物色

`palette.ts` 追加：`bioChloroplast`（绿，叶绿体 / 光合）、`bioMitochondrion`（橙，线粒体 / 呼吸）、`bioGasCo2`（灰）、`bioGasO2`（蓝）、`bioOrganic`（琥珀）。

**理由**：全站色值单一来源是既有约定；且「同一物理量全站同一颜色」意味着后续若有别的生物演示涉及 O₂ / CO₂，可直接复用而非另起一套。

## Risks / Trade-offs

- **信息密度**：微观场景 + 曲线挤在 800×500，1024×768 视口下画布只有 638×400px。→ 曲线压到 170px 高、只标 `0 / 20 / 40 / 60 / 80 / 100` 六处刻度，数值交给 KPI；若 `verify:layout` 出现文本重叠，退化方案是砍掉净速率曲线，只留光合曲线与呼吸水平线。
- **夜间叙事被跳过**：8 秒走完一天，用户可能只看白天的部分就停手。→ 默认从 06:00 起播，`loop: true` 保证夜间必然出现；同时把「净流向」放进 KPI，即使只看一眼也能看到它从「净吸收」变成「净释放」。
- **补偿点时刻会随参数变化**：`Pmax / K / R` 任一改动都会改变 `L_c` 与对应时刻。→ 时刻不由常量硬编码，而由内核从 `L_c` 反解 `sin` 得到，改参数后读数自动跟随。
- **箭头长度编码 `|N|` 可能导致零附近抖动**：`N` 在补偿点附近接近 0，箭头若按比例缩放会变得极短甚至消失。→ 设最小可视长度 8px 并在 `|N| < 0.05` 时直接切换为「收支平衡」标记，避免出现半截箭头。
- **单一变量被稀释**：只要有人后续想加温度滑块，曲线的横轴语义就崩了。→ 在 design 与 spec 中均显式写明「MUST NOT 引入第二自变量」，后续要加需另立 change。

## Migration Plan

无迁移。新增独立路由与独立内核文件，既有演示与共享组件零改动。回滚只需删除新增文件并从 `demos.json` / `App.tsx` / `demoIcons.tsx` 移除对应条目。

## Open Questions

无。参数取值（`Pmax = 30`、`K = 45`、`R = 5`、`dt = 0.05`）已在上面钉死，实施时如需微调只影响数值，不影响 specs、方案或任务拆分。
