# Design

## Context

动机见 `proposal.md`，需求见 `specs/convex-lens-imaging/spec.md`。此处只记录约束与实现决策。

现有实现的关键约束（均已核对代码）：

- `CONFIG` 是组件内普通常量对象，`f: 100` 硬编码于 `src/demos/ConvexLensSim.tsx`，无 state；所有几何计算直接读 `CONFIG`。
- 画布坐标系固定 800×500，`centerX = 400`、`centerY = 250`、物高 `objH = 60`、透镜半高 100。
- 已有 pointer 拖拽模式：`getScreenCTM()` 反变换 + `setPointerCapture`，仅在物距方向生效，`u` 被 clamp 在 10–350。
- 自动演示在 `Math.abs(nextU - f) < 1` 时把 `nextU` 推到 `f - 1.5`，等于主动跳过 u = f。
- 光线只有 `parallel`（平行光轴入射）与 `center`（过光心）两条。
- `calculateThinLens` 已在 `|u - f| < 0.1` 时返回 `typeKey = 'image-type-parallel'`，`v` 与 `m` 为 `Infinity`。
- 侧栏在 1024 堆叠布局下真实内容高度约 136px，可用余量约 304px；1366 及以上行布局中侧栏被 `align-items: stretch` 拉伸，`getBoundingClientRect()` 报告的是行高，不能当作内容高度使用。

## Goals / Non-Goals

**Goals:**

- 在保留现有光路图可读性的前提下叠加光屏交互，不重绘为实物光具座场景。
- 所有新增控件的总高度控制在约 110px 以内，保证 1024 视口下侧栏不溢出。
- 新增状态（焦距、光屏位置、遮挡开关）与既有拖拽/动画/滑块三种输入路径保持单一数据流向，避免出现动画与滑块互相覆盖 `u` 的竞态。

**Non-Goals:**

- 不把画布改造成蜡烛/导轨/刻度的写实光具座场景。
- 不引入 u-v 图像、不引入凸透镜与凹透镜的合并视图。
- 不修改 `calculateThinLens` 的数学实现，不在本页渲染五种情况对照表。

## Decisions

### 1. 光屏作为叠加层，而非场景重绘

光屏实现为画布内一条竖直的浅色半透明矩形（宽约 6px、高约 200px），与像箭头同一层级。拖动仅沿水平方向，与物距拖拽共用同一套 `getScreenCTM()` 坐标转换。

选择理由：光路图本身是该页区别于其他站点的核心资产，三条特殊光线在写实场景里会被遮挡；光屏作为竖线叠加不干扰光线读数。

替代方案：整体改为光具座实物场景。放弃原因是作图题的可读性损失大于实验题的收益，且改动量约为叠加方案的 3 倍。

### 2. 清晰度用阈值判定，不用连续函数

判定式为 `|x_screen - (centerX + v)| <= 6` 像素时判「清晰」，否则「模糊」并给出移动方向提示。`v` 为 `Infinity`（u = f）或 `v < 0`（u < f）时恒判「模糊 / 接不到像」，且不给出移动提示。

选择理由：连续函数会让「清晰」变成一个模糊的渐变，反而弱化「必须在像的位置才能承接到像」这一考点；阈值判定与实验里「前后移动光屏找到最清晰的像」的操作语义一致。

替代方案：按偏差计算模糊半径做高斯模糊视觉模拟。放弃原因是实现复杂且对考点无增益。

### 3. u = f 允许停留，删除跳过逻辑

直接移除 `nextU = CONFIG.f - 1.5` 分支。滑块 step = 1、焦距取整数值，因此 `|u - f| < 0.1` 可精确命中，`calculateThinLens` 已有的平行光分支即可复用。

`v = Infinity` 时像箭头 `opacity(0)`，两条出射光线绘制为平行线，KPI 显示「不成像」。

选择理由：u = f 本身是选择题高频点，跳过它等于把考点抹掉。

替代方案：滑块吸附跳过该点。放弃原因是用户会误以为「拖不过去」是 bug。

### 4. 焦距改为 state，几何计算改为参数化

`f` 从 `CONFIG` 中移出，改为 `const [f, setF] = useState(100)`，`updateScene` 签名扩展为 `(u: number, f: number)`，所有引用 `CONFIG.f` 的表达式改为使用入参。`CONFIG` 中其余常量（画布尺寸、中心点、物高）保持不变。

物距上限随焦距自适应：`uMax = Math.max(350, 3 * f)`，滑块 `max` 与拖拽 clamp 共用该值，保证 `u > 2f` 区段始终可达。

选择理由：保持 `CONFIG` 作为静态几何配置的语义，动态物理参数走 state，避免「常量对象里混入可变值」导致的重绘遗漏。

替代方案：把整个 `CONFIG` 放进 state。放弃原因是每次焦距变化都会让静态元素（主光轴、透镜、焦点标记）跟着重算，代价高且无必要。

焦点标记 `F / 2F / F' / 2F'` 位置依赖 `f`，因此这些标记不能放在 `useSVGScene` 的一次性初始化里，需移入一个独立的重绘函数，在焦距变化时重新定位。

### 5. 遮挡开关只影响像的绘制透明度

开关状态 `occluded` 仅参与像箭头的 `opacity` 计算（完整时 0.7，遮挡时 0.35），不改变 `v`、`m`、成像性质与光屏判定。

选择理由：考点结论是「像仍完整、只是变暗」，任何几何变化都会误导。

### 6. 侧栏控件布局与高度预算

侧栏新增内容按以下顺序排布，总高控制在约 110px：

```
[自动演示][重置]          已有，约 40px
物距 u 滑块                已有，约 44px
焦距 f 滑块                新增，约 44px   <- 与物距滑块同构，复用 ParamSlider
[遮住透镜上半部分] 开关    新增，约 22px   <- 单行文字按钮，不引入新组件
```

光屏位置不使用滑块，只通过画布拖拽调整——侧栏高度预算不足以再容纳第四个控件，且「拖光屏找像」正是实验操作本身。

### 7. 区段标注用主光轴上的浅色区间块

在 `u > 2f`（左侧 2F 以外）、`f < u < 2f`（2F 与 F 之间）、`u < f`（F 与透镜之间）三段绘制低透明度背景矩形，当前区段高亮，并在区段内显示「倒立缩小实像 / 倒立放大实像 / 正立放大虚像」短标签。

选择理由：区段与滑块位置天然对齐，无需额外 UI；透明度控制在 0.08 以下以免干扰光线判读。

### 8. KPI 扩展并复用现有容器

在 `KpiBar` 的 `items` 中追加「像的位置」「能否承接」「像高 h′」三项，但最终卡片数为 5 而非 6：保留 `m`（计算题需要）并把「像高」并入 `m` 的 `hint`，把「能否承接」并入「像的位置」的 `hint`。`KpiBar` 组件本身不需要改动。

实测修正：初版按 6 个卡片设计，实测 1024×768 下画布宽 638px、1366×768 下 636px，每个卡片 `min-w-[6.5rem]`（104px）加 8px 间距，6 卡至少需 664px，必然折成 5+1 两行，KPI 高度由 52px 涨到 132px，挤压画布高度。合并为 5 卡后 KPI 回到 72px 单行。

### 9. 校验脚本补充侧栏内容高度度量

在 `scripts/verify-layout.mjs` 的 `measure()` 中，对侧栏取其最后一个子元素的底边相对侧栏顶边的距离作为「内容真实高度」，新增断言：该值不得超过视口高度。此项不替换原有断言，只作为补充。

选择理由：现有断言在 ≥1280 视口下实际测的是行高，无法发现侧栏内容膨胀；新增度量使 P0 改动的风险可被自动化捕获。

实测修正：初版设计写的是「不得超过堆叠布局下的可用余量」，实测 1024×768 下侧栏顶边已落在 731px，真实余量仅 37px，16 条既有路由全部超限——该基准本身不成立，因为堆叠布局下侧栏允许超出视口并由内容区滚动承接。改用「不超过视口高度」作为基准，现有路由取值 292–420px 全部通过，同时仍能捕获控件膨胀。

另外补充了单路由级重试（最多 3 次，失败前先 `goto('about:blank')` 重置页面）：连续跑 96 次导航时偶发 `Navigating frame was detached`，属于 puppeteer 复用同一 page 的竞态，不是布局问题；重试避免把这类噪声误报为布局失败。

## Risks / Trade-offs

- [光屏与像箭头在 u 接近 f 时位置重叠，视觉上互相遮挡] → 光屏绘制在像箭头之下，且光屏宽度限制为 6px；u = f 时像箭头本就隐藏。
- [焦距变化后焦点标记需要重绘，容易漏掉某次更新路径] → 焦点标记重绘与区段高亮合并为单一 `redrawStatic(f, u)` 函数，由焦距变化与物距变化共同调用，避免两处各自维护。
- [删除跳过逻辑后，自动演示经过 u = f 时 `v = Infinity` 可能产生无效 transform] → 在 `v` 非有限时提前返回，跳过像箭头 transform 与光屏判定，只更新光线与 KPI。
- [侧栏高度预算紧张，新增控件可能突破 110px] → 用新增的校验度量做兜底；若超限，优先把「遮挡开关」移到画布内的浮层（`OVERLAY_AREA_LIMIT` 为画布面积 25%，单行开关远低于该上限）。
- [u 上限随焦距扩展后，大焦距下物体可能被拖出画布左边界] → clamp 上限同时受 `centerX - 20`（画布左边界留白）约束，取 `Math.min(3 * f, centerX - 20)`。
- [元数据补充实验类关键词后与 `/lens-imaging-rules/` 产生关键词重叠] → 两页 keywords 显式分工：本页只保留操作类词（光具座、光屏、焦距可调、实验），对照表页保留信息类词（口诀、五种情况、对照表）。

## Migration Plan

无数据迁移。上线顺序：

1. 修改 `ConvexLensSim.tsx` 与 `demos.json`。
2. 运行 `npm run build:prerender` 重建静态页面。
3. 运行 `npm run og:image` 重新生成 `public/og-convex-lens.jpg`（画布内容已变化）。
4. 运行 `npm run verify:layout` 确认侧栏在 1024 视口不溢出。

回滚：该页为独立路由，回滚仅需还原 `ConvexLensSim.tsx` 与 `demos.json` 两个文件，不涉及路由、sitemap 或数据结构变更。
