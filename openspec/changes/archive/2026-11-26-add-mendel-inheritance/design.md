# Design

## Context

站点当前 12 个 demo 全部属于物理与化学，生物为 0 覆盖；动机见 proposal.md 的 Why。

现有可复用基建：

- `useSVGScene`：挂载时初始化 svg.js 场景，后续由 demo 自行重绘。
- 共享组件：`DemoPage`、`SimulationCanvas`、`DemoSidebar`、`DemoMain`、`KpiBar`、`ParamSlider`、`DemoControls`、`CanvasLegend`、`PrincipleCard`、`DataPanel`。
- 内核目录惯例：`src/lib/physics/*.ts`、`src/lib/chem/solubility.ts` 都是「纯函数内核 + 演示层绘制」的拆分，生物沿用 `src/lib/bio/mendel.ts`。
- 路由与派生资源：`scripts/prerender.js`、`scripts/gen-sitemap.js`、`scripts/verify-layout.mjs` 均从 `demos.json` 派生，新条目自动纳入，无需改脚本。

三条必须遵守的既有约束：

1. `demo-workspace-layout`：侧栏只放控制、KPI 条 4–6 项只放逐帧变化量、恒定派生量单行小字。
2. `demo-canvas-legend`：图例在画布下方正常文档流，不得覆盖画布。
3. `Layout.tsx` 的 `menuGroups` 只有 `math` / `physics` / `chemistry`，侧栏靠 `Demos.filter(d => d.category === group.id)` 分发。`category: "biology"` 的条目在当前代码下**不会出现在任何菜单**，这是本次必须先解决的前置阻塞。

## Goals / Non-Goals

**Goals:**

- 用单一内核（`src/lib/bio/mendel.ts`）产出「配子 → 棋盘 → 基因型/表现型分布 → 随机模拟计数」一条链路的结果，场景与读数全部从同一结果读取，保证画面与读数自洽。
- 让「3 : 1 是概率收敛结果」在画面上可被直接观察，而不是只靠文字结论。
- 让随机模拟可复现，使端到端校验脚本能对计数与比例做精确断言。
- 打通生物学科归类链路，使后续生物 demo 只需在 `demos.json` 写 `category: "biology"` 即可出现在侧栏。

**Non-Goals:**

- 不实现双因子杂交（自由组合定律，9 : 3 : 3 : 1）与连锁互换。
- 不实现「人的性别遗传」（XX × XY）——它讲的是性染色体而非等位基因，概念不同，留给后续独立 demo。
- 不实现基因互作、不完全显性、复等位基因。
- 不实现系谱图判读与概率计算题自动判分。
- 不引入时间轴播放（无 ∫dt 累积量）。

## Decisions

### 1. 独立新页面，slug 取 `mendel-inheritance`

遗传内核（配子分离、棋盘组合、表现型映射）与既有物理/化学内核没有任何共用计算，塞进现有页面只会破坏其需求语义。

名称策略沿用既有约定：`demos.json` 的 `name` 取短名「孟德尔遗传实验」，页面内 `useSEO` 的 title 用完整名。原因是 `name` 同时喂给 Dashboard 三列网格卡片标题，长名会让卡片高度与其他卡片不一致。

### 2. 内核只做「一对等位基因」，接口按单因子收敛

初中（人教八下「基因的显性和隐性」）只讲一对相对性状，双因子是高中必修2 的内容。

```
                本次实现                     排除
  基因对数      1 对（A/a）                  2 对（A/a × B/b）
  棋盘尺寸      2 × 2                        4 × 4
  表现型比      3 : 1 或 1 : 1               9 : 3 : 3 : 1
  画布负载      棋盘 + 比例条，宽松           棋盘占满半屏，比例条无位置
```

内核接口按「基因型为长度 1 的等位基因数组」这一形状定义（`Genotype = [Allele]`，`Allele = 'D' | 'd'`），而不是硬编码成两个字符。这样后续要扩到双因子时，只需把数组长度从 1 放宽到 2 并让棋盘尺寸随长度推导（`4^1 = 2`、`4^2 = 4`），**不需要重写配子生成与表现型映射**。但本次不为双因子写任何代码分支——「为未来预留」只体现在类型形状上，不体现在功能上。

替代方案：直接写死 `'DD' | 'Dd' | 'dd'` 三个字面量。更短，但后续扩展要推翻内核，不取。

### 3. 种子化伪随机数，而非 `Math.random()`

`Math.random()` 不可复现，端到端校验脚本无法对「样本数 1000 时高茎数接近 750」做精确断言，只能断言「大致接近」，这类弱断言在回归时容易漏掉真 bug（例如把 `Dd` 误判成隐性，3:1 会变成 1:1，弱断言可能仍然通过）。

采用 `mulberry32`（32 位整数状态的确定性 PRNG）：

```ts
function mulberry32(seed: number) {
  return () => {
    seed = (seed + 0x6d2b79f5) | 0;
    let t = seed;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

内核签名固定为 `simulate(input, seed)`，同一 `input` + 同一 `seed` 必然产出同一计数序列。侧栏的「重置」把 `seed` 回到默认值；「重新抽样」把 `seed` 递增。

替代方案：`Math.random()` + 只在 UI 层做「看起来稳定」的处理。不可复现，不取。

### 4. 棋盘与比例条上下分屏，共用同一内核结果

画布 `viewBox` 取 800×500：

```
+-------------------------------------------------------+
|  P    DD  x  dd          F1   Dd                      |   遗传图解区（顶部窄条）
+-------------------------------------------------------+
|        配子:  D    d                                  |
|     +---------+---------+                             |
|  D  |   DD    |   Dd    |       <- 棋盘 2x2            |   棋盘区（左上）
|     +---------+---------+                             |
|  d  |   Dd    |   dd    |                             |
|     +---------+---------+                             |
|                                                       |
|  理论 3 高 : 1 矮        +--------------------------+  |   比例条区（右侧）
|                          | 高 ####################  |  |
|                          | 矮 #######                |  |
|                          +--------------------------+  |
|                             n = 1000   实测 752:248    |
+-------------------------------------------------------+
```

上方窄条呈现亲本与配子，左侧棋盘解释「3 : 1 从哪来」，右侧比例条解释「3 : 1 是概率」。三者共用一次 `solve` 的结果，不存在两处各算一遍导致数字对不上的可能。

比例条采用水平双色条（高茎 / 矮茎按实测计数分段），条下方标注实测计数与样本数。理论比例以细虚线刻度标在条上，使「实测偏离理论」在视觉上可量读。

### 5. 不接入 `useSimulation`，样本数变更即时重算

本演示没有随时间演化的物理量：样本数一旦确定，结果就是一次性的统计量，不存在「播放」这一维度。`magnet-coil-induction` 用脚本时间轴是因为磁通量需要以时间积分；这里相反，改样本数即重算整段。

```
              即时重算                 useSimulation 时间轴
  物理量       离散统计量（无积分）     需要 ∫dt 的累积量
  交互成本     低（改参数即重绘）       中（需预计算帧序列）
```

因此侧栏不出现「播放/暂停」按钮，`DemoControls` 只保留「重新抽样」与「重置」两个动作。

### 6. 生物学科归类链路一次性打通

三处改动，缺一处该 demo 就无法正确出现：

| 文件 | 改动 | 不改的后果 |
|---|---|---|
| `src/components/Layout.tsx` | `menuGroups` 新增 `{ id: 'biology', title: '生物', icon: Dna }` | demo 不出现在任何菜单 |
| `src/lib/demoIcons.tsx` | 新增 `'mendel-inheritance': Dna` | 侧栏与卡片显示化学的 `FlaskConical` 兜底图标 |
| `src/lib/palette.ts` | 新增生物语义色（显性 / 隐性 / 基因型标注） | 绘制层只能用散落的十六进制字面量，破坏「颜色即语义」约定 |

分组图标取 `lucide-react` 的 `Dna`，与既有的 `Calculator` / `Atom` / `FlaskConical` 同属线性图标族，视觉权重一致。

`menuGroups` 的默认展开状态 `expandedGroups = ['physics']` 不改动——新增分组默认折叠，符合「默认只展开主学科」的既有观感。

### 7. 表现型名称由内核常量提供，不在绘制层硬编码

`mendel.ts` 导出 `TRAIT = { dominant: '高茎', recessive: '矮茎', gene: 'D / d' }`。棋盘格、比例条、KPI 条、原理卡全部引用同一常量，避免出现「棋盘写高茎、比例条写显性」这类不一致。

替代方案：在绘制层各写一遍中文标签。改动一处就会漏改其他处，不取。

### 8. 读数分层

KPI 条（4 项，全部随输入变化）：样本数 n、高茎数、矮茎数、实测比例（高 : 矮）。

恒定结论单行小字：理论分离比（随亲本组合变化但不由模拟驱动）、显性完全掩盖隐性、配子随机结合、表现型相同不代表基因型相同。

侧栏只放：亲本组合选择（三档）、样本数滑块（4–1000，对数刻度感可用分段档位 4 / 10 / 100 / 1000）、重新抽样按钮、重置按钮。

注意「理论分离比」虽随亲本组合变化，但它由棋盘唯一确定、不随抽样波动，因此不进 KPI 条，放在棋盘区标注——这与「KPI 条只放逐帧变化量」的规则一致。

### 9. 单位与坐标系

画布 `viewBox` 800×500。棋盘格边长 96px，配子行列标签在外侧；比例条宽 220px、高 120px，位于棋盘右侧。所有坐标为常量，不引入物理比例尺——本演示没有需要与真实尺度对应的量。

## Risks / Trade-offs

- [新增侧栏分组可能被视为 `app-shell-layout` 的需求变更] → 该规格要求侧栏按学科分组呈现，新增一个学科分组属于既有需求的自然延伸而非变更；本次不改其任何 requirement，只在归档时确认无 delta 需要。
- [大样本（1000）逐个体绘制会让画布元素爆炸] → 模拟只在内存中生成计数，画布上只画比例条与计数文本，**不逐个体绘制图形**；绘制元素数量与样本数无关，恒为常数级。
- [比例条在小样本下可能出现 0 或全高，导致分段长度为 0 而视觉丢失] → 分段设最小可视长度（2px），同时在计数文本处如实给出 0 值，不用视觉修正掩盖真实数据。
- [随机模拟的「实测比例」在每次渲染都可能被误读为确定值] → 在比例条旁显式标注「实测」与「理论」两个词，并在讲解区说明偏离是正常的。
- [棋盘格在 1024×768 视口下可能被压扁] → 棋盘尺寸按画布 `viewBox` 固定比例计算，`SimulationCanvas` 等比缩放，不依赖视口宽度做布局分支；`verify:layout` 三种视口均需通过。
- [预渲染阶段无交互，画面必须是初始状态的静态可渲染结果] → 初始状态即给出默认亲本组合（`Dd × Dd`）、默认样本数（1000）与完整棋盘 + 比例条，`DemoPage` 挂载后置 `__PRERENDER_READY__`，与既有演示一致。
