# Design

## Context

现有 4 个力学/光学 demo 已经确立了可复用的骨架：`useSVGScene` 负责一次性搭场景，`useSimulation` 负责帧数组回放，`DemoPage` / `SimulationCanvas` / `DemoSidebar` / `ParamSlider` / `DataPanel` / `PrincipleCard` 提供统一布局。纯物理计算一律放在 `src/lib/physics/` 下，与 React / SVG 解耦（参见 `lever.ts`、`fallingBall.ts`）。

单摆和它们有一个本质差异：**它是永不停止的周期运动**，而现有 demo 都是"过程结束后静止"。这个差异带来两个必须单独处理的工程问题：

1. `useSimulation` 播到 `maxTime` 会 `setIsRunning(false)` 并停在终点，对周期运动体验差
2. 现有 `fallingBall.ts` 用的是显式欧拉积分，对短过程无害，对持续振荡会持续注入能量

画布沿用 800×500（与 `LeverBalance` 一致，上一轮修箭头溢出时确立的尺寸）。

## Goals / Non-Goals

**Goals:**

- 用双摆同场竞速，让"等时性只在 θ 小时成立"这一考点肉眼可见
- 精确周期用解析公式给出，使 5° 摆相对 T0 的 0.05% 偏差也能显示（数值测量做不到）
- 能量与受力可视化只做加法，不改动既有 demo 的任何行为
- 曲线图区与摆动画区在同一画布内不重叠、不越界

**Non-Goals:**

- 不做 90° 释放档位（物理上会让绳松弛，见下文决策）
- 不抽取公共的 `polylinePath` / `headPoints` 工具（与既有惯例保持一致，见决策 9）
- 不做阻尼衰减、驱动力、共振（属于后续「弹簧振子」或独立 demo 的范畴）
- 不重构 `useSimulation` 的既有接口语义，只增加可选字段

## Decisions

### 决策 1：积分器用 velocity Verlet，不用显式欧拉

**理由**：显式欧拉对谐振子每步能量放大约 `1 + ω²dt²`。取 L=1 m、dt=0.01 s 时每步 +0.098%，一个周期 200 步即累计 `1.00098^200 ≈ 1.217`——**每摆一个周期振幅涨约 10%**。这会让 θ₀=5° 的摆几秒后甩到 40°，"等时性"演示彻底失真，而且看起来像"振幅越大周期越长"，与要教的结论相反。

velocity Verlet 是辛格式，能量只在真值附近有界振荡，不会单调漂移，振幅稳定，周期对比才有意义。

**备选**：RK4（精度更高但非辛，长时仍有缓慢漂移，且每步 4 次求值，收益不明显）；显式欧拉（能量发散，直接排除）。

**实现**：内部积分步长 `h = 0.005 s`，按 `0.01 s` 采样成帧。单摆方程 `θ̈ = -(g/L)·sinθ`，Verlet 形式：

```
θ_{n+1} = θ_n + ω_n·h + 0.5·a_n·h²
a_{n+1} = -(g/L)·sin(θ_{n+1})
ω_{n+1} = ω_n + 0.5·(a_n + a_{n+1})·h
```

### 决策 2：周期用解析椭圆积分，不用帧数据数零交叉

**理由**：θ₀=5° 的精确周期相对 T0 只差 0.05%。若从 800 帧里数零交叉点，离散误差（帧间隔 0.01 s 对应 0.5% 量级）比信号本身还大，数据面板会显示无意义的抖动数字。

解析式：`T_exact = 4√(L/g)·K(sin(θ₀/2))`，第一类完全椭圆积分 `K(k)` 用算术-几何平均（AGM）求：

```
K(k) = π / (2 · AGM(1, √(1-k²)))
```

AGM 二次收敛，6~8 次迭代即达机器精度。手算校验 L=1 m：`T0 = 2.007 s`、`T_exact(60°) = 2.154 s`、比值 `1.0732`（与文献的 1.0732 一致）。

**备选**：级数展开 `T ≈ T0(1 + θ₀²/16 + ...)`（θ₀=60° 时误差偏大）；查表插值（不必要）。

### 决策 3：θ₀ 上限取 60°，不取 90°

**理由**：绳张力 `T = mg cosθ + mv²/L`。θ₀=90° 释放瞬间 `v = 0`、`cos90° = 0`，于是 `T = 0`——绳当场松弛，摆球脱离圆弧运动，整个模型失效。

θ₀=60° 释放瞬间 `T = 0.5mg > 0`，全程绷紧。而 60° 的周期偏差已达 **+7.3%**：3 个周期后两摆错开约 0.44 s（约 20% 个周期），竞速错拍肉眼完全可辨，不需要冒 90° 的风险。

### 决策 4：`PX_PER_M = 150`，摆长上限 1.0 m

**理由**：两摆必须满足「枢轴间距 300 px > 2 × 最大水平偏移」。θ₀=60° 时水平偏移 `= L·sin60°·PX_PER_M`。取 `PX_PER_M = 150`、`L ≤ 1.0 m` → 偏移 ≤ 130 px，两摆各占 `120..380` 与 `420..680`，中间留 40 px 不打架。

L 滑块范围 `[0.4, 1.0] m`，对应 T0 从 1.27 s 到 2.01 s，跨度足够观察「摆长越长周期越长」。

**备选**：`PX_PER_M = 200`（L=1.0 时偏移 173 px，两摆重叠）；缩小枢轴间距（摆球会互相穿过）。

### 决策 5：`useSimulation` 新增 `loop?: boolean`，默认 `false`

**理由**：单摆永不停歇，播完停在终点观感很差。新增可选字段、默认关闭，现有 4 个 demo 的行为逐字节不变。

**实现**：`loop === true` 时，`next >= maxTime` 不停止，而是回绕到 `0`：

```
if (next >= maxTime) {
  if (loop) return next % maxTime;   // 回绕并保持 isRunning
  setIsRunning(false);
  return maxTime;
}
```

**备选**：在 demo 内部用 `setInterval` 重置 `time`（会与 hook 内部 RAF 竞争，产生跳帧）。

### 决策 6：力矢量只画在大摆上

**理由**：每摆 3 个箭头共 6 个，在 130 px 宽度里会糊成一团。小摆留白，反而让「几乎同步」的对照更清晰。

### 决策 7：质量滑块只影响力箭头长度与能量数值，不影响运动

**理由**：`T = 2π√(L/g)` 里没有 m。滑块拖动后摆的运动完全不变，这本身就是要教的考点，比任何文案说明都直观。数据面板同时显示「质量不影响周期」的对照。

### 决策 8：θ-t 曲线做归一化 `θ/θ₀`，并叠加简谐近似虚线

**理由**：θ₀=5° 与 60° 的真实振幅相差 12 倍，不归一化无法同框。归一化后两条曲线起点都是 1.0，"同形状、不同周期"一眼可见。

大摆的简谐近似虚线取 `cos(√(g/L)·t)`（即归一化后的 `θ₀·cos(ω₀t)`）。它与真实曲线从第 2~3 个周期开始明显分离，正好演示 `sinθ ≈ θ` 的误差来源。

**实现**：800 帧对 SVG path 偏密，按 `每 4 帧取 1` 抽稀到 200 点，用局部 `polylinePath` 拼成 `M/L` 路径。

### 决策 9：`polylinePath` / `headPoints` 在新文件里各写一份局部版本

**理由**：这两个函数现在只存在于 `LeverBalance.tsx` 内部，是局部函数。抽取到 `src/lib/svg.ts` 会改动已归档变更的文件，收益小于扰动风险；与既有惯例（每个 demo 自带绘制小工具）保持一致。

### 决策 10：能量条放在侧栏 HTML，不放画布

**理由**：画布纵向已被「摆动区（y 60..270）+ 曲线区（y 280..470）」占满，再塞能量条必然挤压或越界。侧栏 `DataPanel` 区域改用 HTML 堆叠条，天然不受 viewBox 裁剪。

### 画布布局

```
800 x 500
+------------------------------------------------------------------+
| y=60   ============ 天花板横梁 (x:140..660) ============          |
|           O(250,60)                    O(550,60)                 |
|              |                            |                      |
|              |  L·PX_PER_M = 60..150px    |                      |
|         *    |                       *    |                      |
|      (θ0=5°) |                    (θ0=60°)|  <- 力矢量只画这一侧  |
| y=270 ---------------------------------------------------------   |
| y=280 +--- θ-t 曲线区 (x:90..760) -----------------------+        |
|       |  +1  |                                           |       |
|       |   0  | ~~~小摆 ~~~大摆  ---简谐近似              |       |
|       |  -1  |                                           |       |
|       +------+-------------------------------------------+       |

```

约束核算：θ₀=60° 时大摆摆球最高点在 `y = 60 + 150·cos60° = 135`；最低点（θ=0）在 `y = 210`。重力箭头最长 `m=2 kg → 19.6 N × 2.5 px/N = 49 px`，箭头尖端最低到 `y ≈ 259`，距曲线区顶边 280 仍有 21 px 余量。

## Risks / Trade-offs

- **[公共 hook 改动影响既有 demo]** → `loop` 默认 `false`，未传该参数时走原分支；落地后跑 `npm run build` + 人工回归 4 个既有 demo 的播放/暂停/重置
- **[力箭头或标注越界被 viewBox 裁剪]** → 沿用上一轮教训：箭头像素比例固定（2.5 px/N），标注位置加 `clamp` 到安全区；`m` 上限 2.0 kg 已按 49 px 核算
- **[两摆在高角度时视觉重叠]** → `PX_PER_M=150` + `L ≤ 1.0 m` 已核算留 40 px；L 滑块上限硬约束在 1.0
- **[曲线抽稀后形状失真]** → 每 4 帧取 1，800→200 点；在 8 s / 4 个周期的尺度上 200 点足够平滑
- **[`loop` 回绕导致曲线与摆不同步]** → 摆位置与曲线都由同一个 `currentFrame` 驱动，回绕时二者同时跳回 t=0，天然同步
- **[AGM 在 k→1 时收敛变慢]** → 本 demo θ₀ ≤ 60°，`k = sin30° = 0.5`，`√(1-k²) = 0.866`，收敛极快；同时给迭代次数上限 20 次兜底

## Migration Plan

无数据迁移。改动为纯前端新增 + 一个可选字段，部署即生效。回滚策略：`git revert` 本次提交，无残留状态。
