# Design

## Context

动机见 proposal.md。设计需遵守的既有约束：

- 现有 8 个 demo 共用同一骨架：`src/lib/physics/<topic>.ts` 放纯计算，`src/demos/<Demo>.tsx` 放 SVG 场景与控件，`src/lib/demos.json` 是路由与预渲染的唯一真源。
- 可复用件：[useSimulation](file:///e:/workspace/learn/src/hooks/useSimulation.ts) 只接受 `{ t }` 帧数组、固定 `dt` 推进、`loop` 可选；[useSVGScene](file:///e:/workspace/learn/src/hooks/useSVGScene.ts) 仅挂载时初始化一次，重绘由 demo 自行驱动；[ParamSlider](file:///e:/workspace/learn/src/components/demo/ParamSlider.tsx)、[DataPanel](file:///e:/workspace/learn/src/components/demo/DataPanel.tsx)、[PrincipleCard](file:///e:/workspace/learn/src/components/demo/PrincipleCard.tsx)、[DemoPage](file:///e:/workspace/learn/src/components/demo/DemoPage.tsx) 提供布局与展示。
- [palette.ts](file:///e:/workspace/learn/src/lib/palette.ts) 遵循「颜色即语义」，当前无力、光之外的电磁语义色。
- [prerender.js](file:///e:/workspace/learn/scripts/prerender.js) 与 `vite.config.ts` 从 `demos.json` 派生，无需改动。

参数范围带来的数值跨度是本设计的主要张力：τ = mR/(B²L²) 可达 0.05 s ~ 391 s，收尾速度与总行程跨度更大，因此「固定时长 + 固定比例尺」的既有做法不可直接沿用。

## Goals / Non-Goals

**Goals:**

- 三种驱动模式复用同一积分器、同一帧结构、同一绘制路径，仅在 `F_外` 取值与初值上分叉。
- 任意参数组合下画面可读且数值真实，不通过收窄滑块区间来规避问题。
- 复用既有 hooks 与组件，不修改它们的公共接口。

**Non-Goals:**

- 不引入电感、电容、自感、互感，回路按纯电阻处理，运动方程保持一阶。
- 不做磁铁插入线圈、旋转线圈发电机等其他感应现象。
- 不修改 `useSimulation` / `useSVGScene` 的签名，也不新增依赖。
- 不改造 sitemap 生成方式（本次仅修数据，不改为脚本生成）。

## Decisions

### 1. 三模式收敛为「外力取值」的分叉

状态量仅 `x`（位置）、`v`（速度）。运动方程统一为：

```
dv/dt = (F_ext − B²L²v/R) / m
```

| 模式 | 初值 | F_ext | 求解 |
| --- | --- | --- | --- |
| 1 惯性滑行 | v(0)=v₀, x(0)=0 | 0 | 数值积分 |
| 2 恒力驱动 | v(0)=0, x(0)=0 | 常数 F | 数值积分 |
| 3 匀速拖动 | v ≡ v_target | 反解 = F_A | 代数，不积分 |

**替代方案**：为三种模式写三个独立计算函数。否决理由：绘制、数据面板、能量条、曲线逻辑会三份重复，且后续修正公式需同步三处；统一引擎只让模式差异落在 `F_ext` 与初值上，代码分支集中在一个 switch。

**积分器选择**：沿用单摆 demo 的 velocity Verlet 思路，但本系统是一阶方程且无势能项，故改用等价的半隐式（semi-implicit）欧拉：先更新速度再更新位置。阻尼系统下它比显式欧拉稳定，且比 RK4 更省代码。**替代方案** RK4：精度更高但四倍计算量，在固定 800 帧且步长已受 τ 约束的前提下收益不明显。

### 2. 自适应时长与自适应采样

```
τ      = mR / (B²L²)
duration = 5τ                    (模式 1、2)
sampleDt = duration / 800
stepDt   = min(sampleDt / 5, τ / 20)
总步数    = 800 × (sampleDt / stepDt)
```

**替代方案**：固定 `sampleDt = 0.01`。否决理由：τ 最大约 391 s 时需 195,500 帧，内存与逐帧重绘都不现实；τ 最小时又只有 5 个采样点，曲线会退化成折线。固定帧数把「分辨率」交给时长自适应，两端都保持约 800 点。

**为什么 duration = 5τ**：e⁻⁵ ≈ 0.0067，残余速度小于 1%，肉眼已视为停住；3τ 会留下 5% 可见残速，8τ 则后段画面几乎静止，浪费画布。

模式 3 无 τ 概念，观察窗固定为 3 s，用于呈现 Q 的线性累积。

### 3. 画面缩放：物理真值 + 行程自适应映射

轨道可视长度固定，映射区间取 `[0, x_total]`，其中：

```
模式 1、2：x_total = ∫v dt（由积分结果直接取末帧 x）
模式 3：   x_total = v_target × 3 s
```

轨道旁固定显示「按比例缩放，数值以数据面板为准」。

**替代方案**：收窄滑块区间，把 τ 锁在 0.3–3 s、行程锁在 0.5–4 m，从而固定比例尺。否决理由：会禁止大量合法参数组合（尤其 B、R 的极端值），与「公式验证范围要宽」的教学目标冲突。代价是屏幕速度与真实速度不成正比，用标注诚实说明，与单摆 demo 中「箭头长度以 mg 归一化」的处理方式一致。

### 4. 模式 3 的图表语义切换为 ε–v 特性直线

主图横轴 v、纵轴 ε，绘制过原点直线 `ε = BL·v`，当前工作点随滑块移动；`I ∝ v`、`F_A ∝ v` 通过数据面板数值体现，焦耳热 Q 用数据面板 + 能量条呈现。

**替代方案 A**：时间曲线（v、ε、I 三条水平线 + Q 斜升）。否决理由：三条水平线几乎不携带信息，浪费主图空间。
**替代方案 C**：ε–v 直线与 Q(t) 并排。否决理由：模式 3 需多画一套图，破坏「三模式共用同一绘图函数」的结构，收益不抵复杂度。

实现上仍走同一个 path 绘制函数，只是坐标映射的轴语义由「t → 值」换成「v → ε」。

### 5. 绘制与动画的组织

- 磁场用规则排列的 `×` 符号铺满导轨区域，密度随 B 微调（仅视觉，不参与计算）。
- 回路电流用沿闭合路径流动的小圆点表示，方向由 `sign(v)` 决定，速度由 `|I|` 归一化决定，天然表达楞次定律。
- 两个箭头：`v`（运动方向）、`F_A`（恒反向）；模式 3 额外画 `F_外`，与 `F_A` 等长反向。
- 能量条复用单摆 demo 的三段式（此处为 KE / 已累积 Q），终态 KE→0、Q→KE₀。
- 重绘沿用单摆模式：`useSVGScene` 建静态场景并缓存元素引用，`useEffect` 监听 `sim.currentFrame` 驱动增量更新。

## Risks / Trade-offs

- **[屏幕速度非真实]** 轨道按行程缩放后，棒在屏幕上的一秒对应不到真实一秒 → 画布固定标注「按比例缩放」，所有数值以数据面板为准；数据面板同时显示真实 v、x。
- **[τ 极小时视觉跳变]** duration 仅约 0.25 s，逐帧动画在 60 fps 下只有十几帧 → 曲线用全部 800 个采样点绘制，动画虽粗但曲线连续；并允许拖动时间轴逐帧查看。
- **[模式 3 无时间演化，播放按钮价值弱]** → 播放仍保留，用于展示 Q 的线性累积与能量条变化，而非呈现速度变化。
- **[轨道自动缩放导致跨参数对比失真]** 同一张图不同参数下比例尺不同，无法直接目视比较行程 → 数据面板显示真实行程 x_total，跨组对比以数值为准。
- **[固定 800 帧对极短过程的分辨率上限]** 若 τ 小到动画几乎瞬间结束，800 帧仍可能不够细腻 → 曲线与时间轴拖动是主要观察手段，动画只是辅助。
- **[sitemap 手工维护易再漂移]** 本次修正后仍可能新增 demo 时遗漏 → 在 tasks 中把「更新 sitemap」写成显式步骤，并核对既有条目格式统一为带结尾斜杠。
